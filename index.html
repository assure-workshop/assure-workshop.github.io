About ASSURE-AI

AI-assisted software engineering is becoming part of everyday software analysis, evolution, maintenance, and reengineering. Developers increasingly use AI coding assistants and agentic tools to inspect code, review pull requests, generate patches, repair defects, refactor systems, update dependencies, write tests, and explain vulnerabilities.

While AI tools can improve productivity, their outputs may also introduce vulnerabilities, generate incomplete fixes, produce misleading security explanations, or create unwarranted confidence in insecure code. ASSURE-AI focuses on the evidence, methods, and validation processes needed to support justified security claims about AI-generated or AI-modified software.

Workshop Scope

ASSURE-AI focuses on security assurance for AI-assisted software engineering: the evidence, methods, and validation processes needed to support claims that AI-generated or AI-modified software is secure enough for review, integration, or deployment.

The workshop examines how AI-supported analysis and software-change activities can be assessed, validated, audited, and improved when security is at stake. Relevant activities include vulnerability analysis, code review, pull-request assessment, patch validation, regression analysis, refactoring, migration, modernization, maintenance, security testing, and compliance reasoning.

ASSURE-AI welcomes work on agentic and non-agentic AI tools, static and dynamic analysis pipelines, AI-supported security testing, evidence-grounded evaluation, benchmark and dataset design, auditability, developer review, and human-in-the-loop validation.

Motivation

Productivity gains from AI-assisted development do not, by themselves, establish that the resulting software is secure or ready for deployment. ASSURE-AI addresses this gap by focusing on security claims supported by concrete evidence, such as static and dynamic analysis, security testing, manual review, compliance mappings, repository history, and reproducible benchmarks.

A key concern is false assurance: situations in which an AI tool, agent, review assistant, benchmark result, or explanation gives developers unwarranted confidence that software is secure without sufficient supporting evidence.

Topics of Interest

We welcome submissions on topics including, but not limited to:

Security assurance for AI-generated and AI-modified software artifacts
AI-assisted vulnerability analysis, code review, patch validation, and security testing
Evidence models for supporting security claims about AI-assisted software changes
False assurance, overconfident explanations, incomplete fixes, and developer overreliance
Regression risks and security impacts of AI-assisted refactoring, repair, migration, and dependency updates
Benchmark, dataset, metric, and evaluation design for AI-assisted security analysis
Provenance, traceability, audit trails, and accountability for AI-generated or AI-modified code
Compliance reasoning and evidence-grounded assessment for secure software maintenance
Industrial experience reports on adopting AI assistants or agents in secure development workflows

Call for Submissions

ASSURE-AI solicits original submissions that advance research and practice in security assurance for AI-assisted software engineering. We welcome research contributions, short and position papers, tool and dataset papers, benchmark papers, and industry experience reports.

Submission Type Page Limit Scope
Full papers Up to 8 pages Original research on security assurance for AI-assisted software engineering

Industry experience reports Up to 4 pages Practical experiences with validating AI-generated or AI-modified software changes

Submission Guidelines

All submissions must be written in English and submitted in PDF format. Submissions must follow the official SANER workshop submission instructions and IEEE conference proceedings format. Full papers may be up to 8 pages. All other submission types may be up to 4 pages. Page limits exclude references unless otherwise specified by the official SANER workshop instructions.

Submissions must be original and not under review elsewhere. Each submission will be reviewed by at least three program committee members and evaluated for relevance, clarity, novelty, technical quality, and potential to stimulate workshop discussion.

Workshop Format

ASSURE-AI is planned as a full-day interactive workshop. The program will combine invited and peer-reviewed content with structured discussions to encourage community building around evidence-based security assurance for AI-assisted software engineering.

  • Opening and workshop framing
  • Invited keynote talk
  • Presentations of accepted research, position, tool, dataset, benchmark, and industry papers
  • Industry/practice panel on assurance in deployed AI-assisted development workflows
  • Structured breakout discussion on evidence and benchmark gaps
  • Closing synthesis to identify community priorities and collaboration opportunities
